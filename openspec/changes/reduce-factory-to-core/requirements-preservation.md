# Requirements preservation ledger

This file exists because the refactor's one unacceptable outcome is **losing a measured detail**.

Every numeric window, byte cap, aspect ratio, mask radius, character limit, API pattern, console
page path, legal position and toolchain pin in the current harness was paid for: by an owner
rejection, a failed upload, a killed worker, or a live reading of the Play Console. None of it was
invented, and none of it may be dropped because the program that enforced it was deleted.

**The rule for the implementing agent.** Nothing in this ledger may be removed from the repository
without its **Disposition** being honoured. `DROP` is legal only where this file names what
replaces the protection. If an implementation step cannot honour a disposition, stop and report it
— do not delete the rule, and do not "preserve" it by copying its text into a comment.

**Dispositions**

| Value | Meaning |
|---|---|
| `CORE` | Stays a program check in the reduced core (see `specs/factory-core/spec.md`) |
| `DATA` | Stays a checked-in data file the core reads; the values here are its contract |
| `PROMPT` | Becomes a rule in exactly one agent role prompt (`specs/factory-agent-pipeline/spec.md`) |
| `CHECKLIST` | Becomes a line in a human-readable checklist document a person or agent reads |
| `HUMAN` | Stays a decision the owner makes and states in his own words |
| `DROP` | Removed; the replacement that keeps the protection is named |

Sources are cited as they exist **today**, before the refactor. `MEASURED` / `ON RECORD` /
`INFERRED` labels are used as the repository requires.

## 3. Build-speed discipline (measured, not intuition)

| # | Rule (values) | Source today | Disposition |
|---|---|---|---|
| 3.1 | **One Gradle process per build**: pass every task of one build to a single invocation (`assembleDebug assembleRelease bundleRelease`). Measured on a warm cache: **6.3 s → 2.3 s**. | 3.2 | **Never `--no-daemon`.** `gradleArgs()` throws on it. Keep `org.gradle.caching` and `org.gradle.configuration-cache` enabled. | `.cursor/rules/build-speed.mdc` | `CORE` |
| 3.3 | **Pin one JDK.** Gradle keeps one daemon per JDK. | 3.4 | **`scripts/lib/java.mjs` is the only place that discovers a Java home.** Resolution order: `PLAYKILN_JAVA_HOME` → a supported `JAVA_HOME` → a discovered JDK **preferring major 17**. | 3.6 | Report **cost, not just outcome**: `runGradleTasks` returns `elapsedMs` and `prepare-release.mjs` prints the build time and the resolved JDK (`build JDK <major> (<source>)`). | `.cursor/rules/build-speed.mdc` | `CORE` |
| 3.7 | Build only what the current question needs: `--skip-build` stages already-built artifacts; iteration uses one task, not the release pipeline; a gate whose inputs have not changed is not re-run. | `.cursor/rules/build-speed.mdc` | `CORE` + `PROMPT` |

**2026-09-29** on the app's `Стандартная страница приложения` page, unless the row says otherwise.
The aspect sentence the console states in **every** screenshot field is
`Соотношение сторон изображения должно составлять 16:9 или 9:16`.

## 5. Icon construction and adaptive-icon geometry

The owner rejected the first icons in his own words — *"bad and crooked, a naive silly thing, not a
designed mark"* — and the stated cause was structural: there was no construction grid, no optical
alignment, no declared stroke weight and no negative-space rule, so every mark was nudged into place
instead of built, and the field carried a texture that dissolves into mush in a 48 dp launcher cell.

| # | Rule (values) | Source today | Disposition |
|---|---|---|---|
| 5.1 | **One canvas for both outputs.** The store icon is the flattened adaptive icon: 512 px of a **108 dp** layer, so the listing icon and the installed icon are the same mark at the same size. The previous renderer drew the mark at **0.358** of the 512 px canvas for the listing and **0.268** of the launcher layer — two different compositions of one shape. | `lib/icon_design.py` `CANVAS = 512`, `ADAPTIVE_VIEWPORT_DP = 108` | `CORE` |
| 5.2 | **Adaptive-icon contract**: 108 dp viewport; the launcher mask shows **72 dp**; the guaranteed-visible safe zone is **66 dp** (a circle of that diameter, radius **33 dp**); the floor between the mask edge and a full square mask is **18 dp**. | `lib/icon_design.py`; `check-adaptive-icon.py` (`VIEWPORT_DP 108`, `VISIBLE_MASK_RADIUS_DP 36.0`, `SAFE_RADIUS_DP 33.0`) | `CORE` |
| 5.3 | **The mark stops 2 dp inside the safe circle** (`ADAPTIVE_MARK_CLEARANCE_DP = 2.0`; 9.5 px at 512, comfortably larger than one antialiased pixel), and the round-mark keyline is therefore a circle of radius **31 dp** = **0.287037** of the viewport. | `lib/icon_design.py` | `CORE` |
| 5.4 | **Named keylines as viewport fractions**: trim `0.0`; margin `dp(18) = 0.166667`; visible `dp(72) = 0.666667`; safe `dp(66) = 0.611111`; safe_radius `dp(33) = 0.305556`; clearance `dp(2) = 0.018519`; circle `0.287037`; portrait `0.344444 × 0.459259` (a 3:4 rectangle inscribed in `circle`, half-diagonal `2.5k`); optical centre `(0.5, 0.5)`. Every vertex of every mark is a fraction of this grid — the absolute pixel constants are gone. | `lib/icon_design.py` `GRID` | `CORE` |
| 5.5 | **Declared stroke scale, and nothing else**: `regular = 16/512 = 0.03125`, `bold = 24/512 = 0.046875`. `MIN_FEATURE = regular` is the smallest stroke or counter a mark may declare, and a counter clears the same floor as a stroke, because a counter that fills in is a stroke that changed shape. Marks read as a family instead of as accidents. | `lib/icon_design.py` `STROKE`, `MIN_FEATURE`, `MIN_COUNTER` | `CORE` |
| 5.6 | **48 dp legibility floor**: 16 px at 512 is 3.375 dp in the 108 dp viewport and **1.5 px at 48 dp** — the floor at which a launcher cell shows a line rather than a grey smear; 24 px is 5.0625 dp / 2.25 px. | `lib/icon_design.py` | `CORE` (measured at 48 dp) |
| 5.7 | **Optical, not arithmetic, centring.** A centrally symmetric silhouette has its area centroid at its geometric centre, so no nudge is applied and `optical_offset_px ≈ 0` is the proof rather than a coincidence. A triangular or unbalanced silhouette declares `optical_anchor` in its registry entry. Tolerance **0.02** canvas fractions (10.24 px at 512). | `lib/icon_design.py` `OPTICAL_CENTER`, `OPTICAL_ANCHOR`, `OPTICAL_TOLERANCE` | `CORE` |
| 5.8 | A mark that cannot reach **0.75** of the circle keyline looks lost in its cell (`MIN_REACH_RATIO = 0.75`). The book mark, fitted on its diagonal rather than its width, reaches **0.957**. | `lib/icon_design.py` | `CORE` |
| 5.9 | **One restrained tonal field**: a single exact linear ramp, no drafting grid and no radial bloom. Pillow angle **45.0°** equals Android `android:angle="315"` (Android measures counter-clockwise with 0 = left-to-right; Pillow measures clockwise with 0 = right), which is what makes the store icon and the launcher icon read as one field. | `lib/icon_design.py` `FIELD_ANGLE_DEG 45.0`, `FIELD_ANDROID_ANGLE 315` | `CORE` |
| 5.10 | **Supersampling ×4 then downsample**: Pillow's `ImageDraw` has no antialiasing, so a straight 512 px draw leaves staircase edges on every curve. 4 also makes the declared stroke scale land on whole supersampled pixels (16 → 64, 24 → 96). | `lib/icon_design.py` `SUPERSAMPLE = 4` | `CORE` |
| 5.11 | **Five primitives** — `ring`, `bar`, `plate`, `disc`, `stroke` — declared once in canonical fractions and rendered twice: as pixels and as Android vector path data. The two renderers are separate implementations on purpose and `scripts/test-icon-design.py` measures their agreement rather than trusting it, because a store icon and a launcher icon that drifted apart is exactly the defect this replaces. | `lib/icon_design.py`; `test-icon-design.py` (649 lines) | `CORE` (the agreement check is one of the few suites that stays) |
| 5.12 | **Adaptive-icon XML**: `ic_launcher.xml` and `ic_launcher_round.xml` must reference the **same** foreground; the foreground must resolve to exactly one local `@drawable`/`@mipmap` XML; an unsupported reference and an ambiguous resolution both refuse rather than guess. | `check-adaptive-icon.py` `resolve_foreground` | `CORE` |
| 5.13 | **The path reader supports `M/m L/l H/h V/v A/a Z/z`**, including relative forms, repeated coordinate shorthand (`M x,y x2,y2` implies lineto; `l 1,2 3,4` repeats) and implicit linetos. Treating relative commands as absolute was the original defect — it returned a plausible-looking point list measured from the origin, so a relative-path generator change would have kept the check reporting PASS while the shipped mark was clipped. | `check-adaptive-icon.py` `points_from` + `--selftest` | `CORE` |
| 5.14 | **Arcs are measured as circular arcs only**: `ry` and `x-axis-rotation` are ignored, the generator emits only `a rx,rx 0 …`, and an arc with `rx != ry` is **rejected loudly** (tolerance `1e-6`) instead of being measured as if it were circular — a silently wrong reach is worse than a refused check. There are no beziers in the subset, so a curve command is skipped rather than approximated; that limitation is stated, not hidden. | `check-adaptive-icon.py` docstring + `_arc_points` | `CORE` |
| 5.15 | **The check reads the path data out of the shipped file** rather than retyping the geometry, so it cannot pass on a stale copy. | `check-adaptive-icon.py` main | `CORE` |

## 16. Verification discipline (the rules that must survive as rules)

| # | Rule | Source today | Disposition |
|---|---|---|---|
| 16.1 | **Never claim a script works until it has run.** "The code looks correct" is not evidence. If a script cannot be run, say so explicitly instead of implying it works. | `.cursor/rules/verification-discipline.mdc` | `PROMPT` (this is the rule the reduced core is built to make affordable) |
| 16.2 | **Recursive copies must filter.** Any `cpSync` / `Copy-Item -Recurse` over a project tree excludes `build/`, `.gradle/`, `.kotlin/`, `.idea/`, `.cxx/`, `dist/`, `captures/`, `*.apk`, `*.aab`, `*.jks`, `*.so`, `local.properties`, `keystore.properties`. | 16.3 | **Text rewriting must never touch binary files**: skip files containing NUL bytes and match whole tokens, because a rewrite that fires inside a binary silently corrupts it and is invisible until a build fails. | `.cursor/rules/verification-discipline.mdc` | `CORE` |
| 16.4 | **One source of truth, imported — never restated.** A value used by two programs lives in one module and is imported. ## 18. What the implementing agent must not do

1. **Do not delete a file before its ledger rows are honoured.** Every `CORE` / `DATA` row must have
   a named successor in the new layout, and the successor must exist and run before the source is
   removed.
2. **Do not convert a `PROMPT` row into a regex.** The whole point of the disposition is that
   judgement leaves code. If a rule feels too important to trust to a prompt, the correct change is
   to state it in the owner's review checkpoint, not to re-add a gate.
3. **Do not "preserve" a rule as a comment or a docstring.** A rule that no artifact enforces and no
   person reads is a deleted rule with extra steps.
4. **Do not silently narrow a numeric window.** Every number in §4, §5, §7, §11 and §15 is
   load-bearing; a change to one is a product decision that needs the owner.
5. **Do not add a new gate while doing this work.** New checks are governed by
   `specs/factory-gate-admission/spec.md`, and "the refactor needed it" is not a recorded incident.
6. **Do not measure by intuition.** If a step claims a reduction, it reports the same measurement
   that produced the baseline table in `proposal.md` — a walk of `scripts/` counting files and
   lines, and the one verify command's wall clock.
