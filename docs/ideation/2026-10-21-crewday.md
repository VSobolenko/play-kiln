# Crewday — multi-site construction daily log (one unlock)

**Date:** 2026-10-21  
**Recommended slug:** `crewday`

## The wedge (one sentence)

Crewday keeps an **offline multi-site daily log with captioned photos and a PDF/share handoff under a single unlock** — instead of trapping the same job behind a **yearly subscription** or an enterprise construction suite.

## Revenue arithmetic (division shown)

| Play share (assume 30%) | −$4.50 |

| Serving cost (server/API) | **$0** — on-device photos + local PDF; no account backend |

| Sales / month needed at that target | **~48** |

**Archetype chosen:** `purchase_led_single_unlock` (billing).  
**Rejected alternatives (revenue terms):**

- **Subscription** — banned by factory rule; also the #1 complaint class on this shelf (45% of critical sample).
- **Ads-led** — possible (Snappii already runs ads+IAP at 50K+), but a foreman writing a report on-site is a poor ad surface; ads would undercut the trust promise that rejects subscription traps. Rejected for *this* audience, not because ads are forbidden.
- **purchase_led_repeat_sales** — no recurring consumable cost to fund; daily log is durable local data.

Roughly **40–70 agent hours** for domain model, captioned camera/picker entries, PDF export, billing unlock, settings, localisation, device journey. No server.

## Permissions and capabilities

- **Photo Picker / gallery** — attach existing site photos (no runtime permission).
- **Camera** (`CAMERA`) — optional capture on the walk; job loses live capture without it but picker still works.
- **Share / export** — `PdfDocument` + `ACTION_SEND` / `ACTION_CREATE_DOCUMENT`.
- **No** account, location permission (location is a typed tag, not GPS), Bluetooth, or notifications in v1.

## Device capabilities

Each capability is answered `used` or `not used`; a `used` line names the API and what the job loses without it.

- camera: used — `ActivityResultContracts.TakePicture` / CameraX `ImageCapture` with `CAMERA`; without it a foreman on the walk cannot capture a site photo that is not already in the gallery.
- photo picker / gallery: used — `ActivityResultContracts.PickVisualMedia` (no runtime permission); without it existing site photos cannot enter the daily entry.
- media playback or capture: not used — still photos only; no video or audio recording.
- microphone: not used — the daily log is typed notes and photos, not voice.
- location: not used — site/location is a typed tag, not GPS; no location permission.
- motion sensors: not used — no IMU-driven workflow.
- contacts / calendar: not used — handoff is share/PDF, not address book or calendar writes.
- notifications / reminder: not used — v1 has no reminder surface.
- home-screen widget: not used — v1 keeps logging inside the app.
- share / export: used — `PdfDocument` plus `ACTION_SEND` / `FileProvider`; without it the office never receives the daily report off the phone.
- Bluetooth / USB: not used — no paired field hardware.
- files / SAF: used — `ACTION_CREATE_DOCUMENT` for durable PDF filing; without it the report cannot be saved to a folder the user chooses.
