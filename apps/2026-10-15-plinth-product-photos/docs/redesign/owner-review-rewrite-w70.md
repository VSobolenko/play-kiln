### B. Measured root causes (code/server)

#### B1. AutoCard scene / gradient, categories and duplicate original

**MEASURED — local composition, not a generative request.** `K\ui\PlayKilnApp.kt:477-509` loads `app\src\main\assets\autocard\scene-recipes.json`, supplies `loaded.image.source` and `loaded.image.mask`, and constructs a canvas with the source dimensions. It does not supply `sceneBackgrounds`. `K\ui\autocard\AutoCardScreen.kt:176-184` defaults that map to empty; `:253-277` constructs `AutoCardInput` and calls `AutoCardEngine.compose`. The first clothing recipe is PROCEDURAL, followed by GRADIENT/SOLID and three GENERATED prompt recipes (`app\src\main\assets\autocard\scene-recipes.json:5-12`); a prompt in an asset is not evidence of a model call.

**MEASURED — why it looks like padding.** `K\data\import\ProjectImageLoader.kt:16-26` loads the imported source and constructs an entirely opaque `0xff` mask, not the saved cutout. `K\domain\autocard\AutoCardEngine.kt:339-363` locally renders a PROCEDURAL scene or requires supplied scene pixels; `:377-401` implements that procedural scene as a gradient plus a floor/horizon blend. `K\domain\pipeline\Compositor.kt:35-53,92-95` fits and centers the mask bounds over a background. Its GRADIENT branch is `PixelBuffer.gradient` (`:111-117`). **INFERRED:** an all-opaque rectangular photo is fitted onto a larger field rather than having its original background removed; exposed margins become the “scene.” A particular screenshot's exact padding is not measured here.

**MEASURED — generated recipes are not silently generated.** `K\ui\autocard\AutoCardScreen.kt:373-376` marks generated scenes unavailable when background pixels are absent. `K\domain\autocard\AutoCardEngine.kt:348-356` returns `SceneAssetUnavailable`; it does not call the server or silently turn missing generated assets into gradients. The local procedural path and the server O-07 path must not be conflated.

**MEASURED — taxonomy versus usability.** `K\domain\autocard\AutoCardEngine.kt:24-46` defines 21 categories, including small electronics and OTHER. `K\ui\autocard\AutoCardScreen.kt:167-172,210,283-284` initializes without recognition unless a category is supplied and waits for a recognition attempt; `:537-574` exposes recognition and manual choice when no category exists. **ON RECORD:** O06 says this taxonomy/interaction is inadequate. **UNVERIFIED:** which missing category and which exact repeated-tap state occurred; the next device replay must record the selected product, category and recognition response. **MEASURED — duplicate original.** `K\ui\autocard\AutoCardScreen.kt:613-631` renders a separate source-photo surface, then `:640-664` adds Original/Card preview chips and a preview that can show the source again. This directly accounts for O04's redundant original surface.

### D. Rewrite principles (derived from owner + measured defects only)

- **Preserve input identity across entry, tool and result.** Choose explicit photo/tool context over parameterless Studio entry and saved-output-as-source ambiguity (O07/O10/O13/O14; B2). Require a traceable input/output replay before accepting a tool.
- **Generative creation must actually generate the requested edit.** Reject padding/gradients sold as AI and generic text-to-image masquerading as a photo edit (O03/O12/O18; B1/B3). Local composition is not proof of this promise.
- **Pick photo → pick AI tool → generate.** Reject scene selection mixed into all tools and funneling Create into one local scene path (O05/O12/O15; B6). Keep the first impression short; remove draft/developer jargon.
- **Give each tool its own server-owned instruction contract; user instruction is optional.** Reject making a generic shared prompt mandatory or treating “want white” as the whole recolor contract (O09/O14/O18; B3/B7). Infer product/context when possible; do not claim a prompt alone guarantees fidelity.
- **Show cost on Generate, without a detour that blocks intent.** Reject balance/reservation prose dominating entry and a redundant cost-confirmation modal; preserve real price/credit checks and safe resumption internally (O08/O09/O13; B7).
- **One comprehensible preview context.** Reject the duplicate original surface and a generated variant visually impersonating the selected input (O04/O07; B1/B2).
- **A viewer must reach image detail, and Cutout gets icon undo/redo/zoom.** Reject “dependency installed” as viewer proof and text-only editing controls as fulfillment; do not broaden into a Photoshop clone (O02/O11/O18; B4/B5).
- **Recognition/category choice must help, not impose repeated work.** Reject counting categories as evidence that the owner's product is covered (O06; B1). Verify the actual product/category path.
- **Replace the reviewed Pack/Batch destination with Profile carrying credits, wallet and generation history.** Reject preserving a batch tab merely because the previous design proposed it (O16; B6/C). Do not invent additional Profile functions.
- **Consumer UI must not expose protocol IDs or developer statuses.** Reject raw job names, IDs and settlement explanations as the main interaction; retain internal IDs, truthful money outcomes and actionable failures (O09/O17; B7/B8).
- **Use the owner's pending AI-bearing title only through a separate naming decision/update.** Reject silently changing `naming.json` in W70 or treating the pending pick as already landed (O01).
- **Verify behavior, not tasteful self-description.** Reject release acceptance based on source presence, valid PNGs or transport success; replay the owner's exact failures and separate documented competitor facts from guesses (O19; B3/B5/C).
